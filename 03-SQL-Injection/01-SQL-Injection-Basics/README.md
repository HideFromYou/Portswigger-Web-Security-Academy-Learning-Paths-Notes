# SQL Injection Basics

## Overview

SQL Injection (SQLi) is a vulnerability that allows an attacker to interfere with SQL queries generated by an application.

The basic flow is:

```text
User Input → Web Application → SQL Query → Database
```

If user-controlled input is inserted into an SQL query without proper handling, the attacker may be able to modify the query's logic.

---

## Detecting SQL Injection

Basic techniques used to identify SQL injection include:

- Adding a single quote `'` and observing the response.
- Using SQL-specific syntax that changes the application's behavior.
- Comparing TRUE and FALSE conditions.
- Testing time delays.
- Using OAST when the application gives no useful response.

Example:

```text
' AND 1=1--
```

vs.

```text
' AND 1=2--
```

If the application's response changes between the two requests, this can indicate SQL injection.

---

## Retrieving Hidden Data

SQL injection can be used to modify the logic of a `WHERE` clause.

Original query:

```sql
SELECT * FROM products
WHERE category = 'Gifts'
AND released = 1
```

Payload:

```text
Gifts'--
```

The `--` starts an SQL comment, causing the rest of the query to be ignored.

The resulting query is:

```sql
SELECT * FROM products
WHERE category = 'Gifts'--'
AND released = 1
```

This removes the `released = 1` restriction and can expose products that were not supposed to be displayed.

---

## Subverting Application Logic

SQL injection can also modify authentication logic.

Example login query:

```sql
SELECT * FROM users
WHERE username = 'wiener'
AND password = 'bluecheese'
```

Payload:

```text
administrator'--
```

The resulting query is conceptually:

```sql
SELECT * FROM users
WHERE username = 'administrator'--'
AND password = '...'
```

The password condition is commented out, demonstrating how SQL injection can alter application logic.

---

## Where SQL Injection Can Occur

SQL injection is not limited to `SELECT` queries.

User input may be incorporated into:

- `WHERE` clauses
- `INSERT` statements
- `UPDATE` statements
- `DELETE` statements
- Table or column selection
- `ORDER BY` clauses

The important testing mindset is:

```text
Where does my input reach the SQL query?
```

---

## Basic Testing Workflow

```text
1. Identify user-controlled input
        ↓
2. Test for SQL syntax
        ↓
3. Compare application responses
        ↓
4. Determine whether the query logic can be modified
        ↓
5. Identify what data or functionality can be accessed
```

---

## Key Takeaways

- SQL injection occurs when user input can interfere with an SQL query.
- `'` can be used as an initial syntax test.
- Boolean conditions such as `1=1` and `1=2` can reveal differences in application behavior.
- SQL comments such as `--` can remove the remaining part of a query.
- SQL injection can expose hidden data and modify application logic.
- Always determine where user-controlled input is inserted into the SQL query.
